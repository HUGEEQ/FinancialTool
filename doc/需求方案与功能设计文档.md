## 0. 本文档相对原稿的修订说明

原《需求设计.md》V1.0 的定位是"输入科目余额表 → 自动生成资产负债表/利润表/现金流量表三张报表"。经对实际模板的解析，需求实际为：

> **三张财务报表（资产负债表、利润表、现金流量表）与科目余额表共 4 张表作为输入，按"生成的数据"Sheet 中的计算逻辑列，自动计算 37 项（70 行）财务数据，输出 1 张汇总表。**

主要修订：

| 项 | 原稿 V1.0 | 本版 V2.0 |
|---|---|---|
| 输入 | 科目余额表（三张报表为模板/输出） | 4 张表均为输入 |
| 输出 | 三张报表 | 1 张「财务数据计算结果」汇总表 |
| 计算规则来源 | 外置 `mapping.json` 由人工定义 | 以模板 D 列"计算逻辑"为准，固化为映射配置 |
| 精度规则 | 保留 2 位小数 | 统一 ÷10000 后四舍五入保留 0 位（万元） |
| 人工数据 | 未涉及 | 新增（平均职工人数等 4 项人力数据） |
| 试算平衡 | 强制阻断 | 保留为校验项（科目余额表借贷平衡） |

## 1. 背景与目标

### 1.1 现状与痛点

财务人员每月需按固定模板手工编制"生成的数据"汇总表：从资产负债表、利润表、现金流量表、科目余额表中逐项查找、抄录、换算（÷10000 取整），共 37 项 70 行数据。存在问题：

- **工作量大、易出错**：模板样例数据中已发现与自身规则不符的取值（见 13.3 节样例校验记录），证明手工编制存在实际差错风险；
- **口径不统一**：舍入方式（四舍五入/截断）、分项汇总顺序无明确规范；
- **不可追溯**：手工填数无法留下"每个数从哪张表哪个科目来"的痕迹，复核成本高。

### 1.2 核心目标

用户上传 4 张输入表，工具按固定计算逻辑自动生成 1 张「财务数据计算结果」汇总表：

1. **准确**：金额全程 `Decimal` 精确计算，逐项与计算规则一致，导出前自动勾稽复核；
2. **可追溯**：每个输出值可回溯到源表、源行（科目/项目名称）、源单元格、原始金额、换算过程，留计算日志；
3. **可复核**：主界面结果区按输出表逐行展示计算项与校验状态（✓/✗/⚠/待录入），人工逐项审核确认后才导出落盘；
4. **本地化**：全程离线运行，不上传、不联网。

### 1.3 业务范围

| 范围内 | 范围外 |
|---|---|
| 读取 4 张输入表（结构校验、取数、换算） | 生成资产负债表/利润表/现金流量表本身 |
| 计算 37 项 70 行财务数据 | 账务处理、凭证、结账 |
| 输出「财务数据计算结果」汇总表（保留模板格式，含原始值/取整后双列） | 数据修正/调账建议 |
| 勾稽校验、计算日志、审计摘要 | 多账套并行核算 |
| 人工数据（职工人数等）录入 | 联网取数、报表上报接口 |

## 2. 输入规范（基于模板实测）

4 张输入表支持三种提供方式（默认均支持，见开放问题 Q1）：

- **方式 A**：1 个 `.xlsx` 工作簿，含 4 个 Sheet（与模板一致）；
- **方式 B**：**文件夹**，内含 4 个报表文件（文件名含表名即可自动识别，支持子目录）；
- **方式 C**：**`.zip` 压缩包**，内含同上结构的 4 个报表文件（解压到临时目录读取，用完清理）。

### 2.1 资产负债表

| 项 | 说明 |
|---|---|
| 结构 | 左右双栏：左侧资产（A=项目, B=行次, C=期末余额, D=年初余额）；右侧负债和所有者权益（E=项目, F=行次, G=期末余额, H=年初余额），约 50 行 |
| 本工具取数列 | **期末余额**：资产类取 C 列，负债/权益类取 G 列 |
| 关键项目 | 货币资金、应收票据、应收账款、存货（其中：原材料、库存商品）、流动资产合计、资产合计、应付票据、应付账款、流动负债合计、负债合计、归属于母公司所有者权益合计、所有者权益合计 |

**注意**：
- 项目名称含大量全角空格（`\u3000`）缩进，匹配前必须做名称规范化（见第 6 章）；

## 3. 输出规范

输出文件包含 1 个 Sheet：**「财务数据计算结果」**，由工具**全新生成**（不复制模板，无颜色/填充/边框样式，无计算逻辑列），保证输出干净、可直接用于上报。

| 列 | 内容 | 处理方式 |
|---|---|---|
| A | 项目名称（含层级缩进，与输出模板 A 列一致） | 取自模板 A 列名称基准 |
| B | 行次（1–70） | 工具写入 |
| C | **原始值(万元)** | **工具计算写入**；C1 表头写为 `{报表月份}本年累计 原始值(万元)`；存**全精度** Decimal、显示 2 位（千分位），点单元格可见完整值，×10000 可精确还原到元 |
| D | **取整后(万元)** | **工具计算写入**；D1 表头写为 `{报表月份}本年累计 取整后(万元)`；即最终写入报表的取整值 |

> - 不设「取数来源」「计算逻辑」列——取数链路在主界面钻取明细展示，底稿文件留存完整过程；
> - 人数类（行次 57–60）单位为「人」，不换算；C/D 列该四行直接填人数；
> - 无填充颜色、无边框样式；冻结首行、预设列宽，便于查看。

### 3.1 数值规则

- **换算**：所有数值项 = 原始计算结果 ÷ 10000（元 → 万元）；
- **舍入**：四舍五入保留 0 位小数（`ROUND_HALF_UP`），输出为整数；
- **精度**：中间计算全程 `Decimal`，不做提前取整；仅在最终写入前统一舍入（舍入顺序的口径问题见 13.2 Q2）；
- **空值**：源数据为空视为 0；标注"如无此项填 0"的项目按常量 0 处理（可配置覆盖）；
- **负数**：以 "-" 号直接写入数值（如净利润 -3181）；
- **原始值展示**：结果区每行同时展示原始值（÷10000 后，万元）与取整后对比（见 9.2），计算日志保留完整精度。

### 3.2 输出文件管理

- **文件写入仅发生在用户点击「导出 Excel 报表」之后**（见 9.2/9.3），预览阶段数据驻留内存，不产生中间文件；
- 文件名：`财务计算结果_{YYYY-MM}_{时间戳}.xlsx`（时间戳取运行编号前两段；同秒重名自动加运行编号后缀防覆盖）；
- 工作表名：**财务数据计算结果**；
- 输出为全新生成的工作簿：无填充颜色、无计算逻辑列；冻结首行、预设列宽（A=36/B=8/C=D=18）；
- 导出时：写临时文件 → 回读复核通过 → 重命名为正式文件；失败则清理临时文件，不产生半成品；
- **写入策略为"全写值"**：C/D 两列一律写计算值，保证回读复核可行与审计确定性（见 10.7）；
- 计算输出文件 SHA256 记入审计摘要。

## 5. 项目/科目名称匹配设计（关键机制）

匹配分两步：**先按表头定位列结构，再按名称匹配行**。行号完全不固定（全表扫描，错行/增删行免疫）；列也不硬编码，按第 1 行表头文本动态定位，定位失败即阻断（VC-24），绝不静默读错列。

```text
第 1 行表头 → 定位名称列（「行次」表头左一列）与值列（期望表头文本）→ VC-24
原始名称 → 规范化 → 配置映射匹配 → 匹配数≠1 则报错（VC-09/10）
```

定位规则：

| 表 | 名称列锚点 | 值列锚点（期望表头文本） |
|---|---|---|
| 利润表 | 「行次」左一列（A/F） | 本年实际数（E/J） |
| 资产负债表 | 「行次」左一列（A/E） | 期末余额（C/G） |
| 现金流量表 | 「行次」左一列（A/E） | 本年累计金额（C/G） |
| 科目余额表 | 科目代码列 A（固定） | 两级表头：第 1 行分组（年初余额/期初余额/本期发生额/本年累计/期末余额）× 第 2 行借/贷，定位 10 个字段列 |

- 定位失败（表头缺失/重复/列序不符双栏结构）→ `ParseError(VC-24)`，**E 级阻断**，消息附第 1 行实际表头全文，人工据此修正导出表格格式后重跑；
- 列结构整体平移（如导出文件增减期间列）→ 自动跟随定位，无需改配置；
- 每次运行实际定位到的名称列/值列/表头记入审计摘要**结构快照**，可追溯"本次读的是哪列"。

### 5.1 名称规范化规则

1. 去除全角空格（`\u3000`）、半角空格、Tab；
2. 去除栏目前缀：`一、`、`二、`、`三、`、`四、`、`五、`、`六、`、`七、`、`八、`、`加：`、`减：`、`其中：`、`*`；
3. 去除括号说明（全角/半角括号及其内容）：如 `（亏损以"－"号填列）`；
4. 统一全角/半角标点。

示例：`　　加：公允价值变动收益（损失以“-”号填列）` → `公允价值变动收益`。

### 5.2 三张报表项目的映射配置

输出 70 行中每一条报表类取数规则在 `mapping.json` 中显式配置：

```json
{
  "config_version": "2026.11.1",
  "source_type": "IS",
  "sheet": "利润表",
  "column": "E",
  "match_name": "营业收入",
  "aliases": ["一、营业收入"],
  "match_mode": "normalized_exact",
  "empty_as_zero": true
}
```

- `match_mode` 支持 `normalized_exact`（规范化后精确）与 `contains`（规范化后包含，作为兜底）；
- 匹配到 0 个 → E 级错误；匹配到多个 → E 级错误；`contains` 命中多个候选时取最长匹配并记 W 级警告。

### 5.3 科目余额表的映射配置

科目名称采用 `_` 拼接的全称，**不做**规范化拆解，按全称精确匹配（样例科目均为唯一全称）：

```json
{
  "source_type": "TB",
  "match_name": "长期借款_银行贷款",
  "field": "本年累计借方",
  "sign": 1
}
```

- `field` 取值：`本年累计借方(I)` / `本年累计贷方(J)` / `期末借方(K)` / `期末贷方(L)`；
- 聚合项（应交税费总额等）以科目清单数组表达求和/求差；
- 不按科目代码匹配（各单位编码体系可能不同，见 Q7），但配置中可附 `expected_codes` 作为校验性提示（W）。

## 6. 校验体系

校验结果分三级：**E**（错误，阻断导出）、**W**（警告，导出前须人工确认）、**I**（提示）。校验结果除汇总展示外，按 6.1 节映射为**输出表行级状态**，供主界面结果区逐行显示。

**面向财务人员的呈现（V2.7）**：界面不显示规则编号，只显示中文标题；编号保留在日志与「查看底稿」中供追溯。数据核对按表分组展示（资产负债表/利润表/现金流量表/科目余额表/跨表核对/报表结构），差异金额一律按**万元**（需精确到元时看结果表 C 列全精度原始值或钻取明细）。

| 编号 | 规则（界面标题） | 级别 |
|---|---|---|
| VC-01~07 | 输入结构与数据合法性（见 2.5）：「文件无法读取」「找不到必需报表」「报表没有数据行」「科目代码重复」「金额不是数字」等 | E/W |
| VC-08 | 映射配置 JSON Schema 合法、版本号存在 | E |
| VC-09 | 报表中找不到对应项目（每条报表类映射恰好命中 1 个源项目） | E |
| VC-10 | 科目余额表中找不到对应科目 | E |
| VC-11 | 有余额/发生额的科目未被任何映射使用且不在忽略清单 | W（可配置为 E） |
| VC-12 | 科目余额表借贷不平衡（年初/期初/期末，**按一级科目汇总**；全表合计因层级重复列示无意义） | E |
| VC-13 | 资产负债表不平衡：资产 ≠ 负债 + 所有者权益 | E |
| VC-14 | 资产负债表：流动+非流动资产的合计 ≠ 资产合计；流动+非流动负债的合计 ≠ 负债合计 | E |
| VC-15 | 利润表不平：营业利润与「收入−成本−费用±减值±收益」算出的结果不符 | E |
| VC-16 | 利润表不平：利润总额 ≠ 营业利润+营业外收入−营业外支出；净利润 ≠ 利润总额−所得税费用 | E |
| VC-17 | 现金流量表勾稽关系不符（流入−流出=净额；净增加额=三大活动+汇率；净增加额=期末−期初） | E |
| VC-18 | 跨表不符：资产负债表「货币资金」≠ 现金流量表「现金的期末余额」 | W |
| VC-19 | 报表数与科目余额不符（抽查清单可配置 + **已知口径差异**：如报表"其他应收款" = 科目余额 − 坏账准备，实测差 87,991.56 元恰为信用减值损失） | W / I |
| VC-20 | 计算公式存在循环依赖 | E |
| VC-21 | 人工数据完整性：CLI 未提供 `--manual`（或空槽位）时对应行"待填报"（E）；合理性提示如劳务派遣人数 > 0 而费用 = 0（I）。**人数为 0 是有效值**（如本期无劳务派遣），界面端始终原样提交，不视为缺失（V2.11） | E / I |
| VC-22 | 输出目录不可写 | E |
| VC-23 | 导出文件回读复核不符（写入后重读 D 列严格比对、C 列容差比对，与表头一并校验） | E |
| VC-24 | 报表格式无法识别（表头定位失败）：消息附实际表头全文，便于人工修正输入表格 | E |
| VC-25 | 报表行次不连续，可能串行（错行/重复行探针；跳号允许，无行次行跳过） | W |

**确认与阻断逻辑（V2.10 逐项确认 + V2.18 差异接受）**：
- 导出条件 = **无未接受的 E 级校验差异** + 无 ⏳ 待填报 + **全部项已人工确认**，三者缺一导出禁用（按钮置灰 + 悬停提示缺什么）；
- **公司特殊口径放行**：上传的 4 张表默认正确，若某条核对按标准财务口径不符、按本公司口径可接受——在数据核对问题列表点「**接受差异**」填写原因放行（多条可「全部接受差异」一键处理），或随时「撤销接受」重新阻断；接受记录逐条写入审计摘要与底稿；
- **规则级配置**（mapping.json `validation` 段，适合固化本公司口径）：`severity` 将默认 E 级规则降为 W/I（仅放宽、不加严）、`enabled=false` 关闭规则、`tolerance` 容差（元）+ 全局默认容差；CLI 用 `--accept-checks` 批量接受；
- 人工确认：结果区「确认无误」列逐项勾选（或工具条「全部确认」）；确认记录（行次、项目、状态）写入操作日志与审计摘要。

### 6.1 行级校验状态模型（预览审核用）

校验结果除表级汇总外，须挂接到输出表 70 行的**行级状态**，在主界面结果区逐行呈现"成功打勾 / 失败打叉"：

| 状态 | 图标 | 含义 | 触发规则（示例） |
|---|---|---|---|
| 通过 | ✓ | 取数命中且复算通过 | VC-09/10 唯一命中、勾稽在容差内 |
| 失败 | ✗ | 阻断级问题，导出禁用 | VC-09/10 未命中或多命中、VC-13~17 勾稽超差、VC-20 循环依赖、VC-23 回读不符 |
| 警告 | ⚠ | 非阻断，导出前须确认 | VC-18/19 跨表口径差异（已知口径差异外）、`contains` 多候选提示 |
| 待填报 | ⏳ | 人工数据未提供（仅 CLI 未传 --manual；界面端 0 为有效值，不触发） | VC-21（行次 57–60） |
| 常量 | ○ | 固定值项按默认配置填列 | CONST 类 |

**真空单元格语义（V2.4 修订）**：源单元格为空（区别于显式 0）时按 0 填列，**结果正确即 ✅ PASS**，附加 I 级提示消息「对应报表单元格为空，按 0 填列」——在来源列、钻取明细（含单元格地址）中可见，状态图标带 tooltip，但**不标记异常**、不进"只看需要关注的行"过滤、不要求导出前确认。⚠️ WARN 仅保留给真正需要人工判断的场景（跨表口径差异、多候选匹配）。勾稽校验（VC-13~19）持续对按 0 填列的结果做交叉验证，若空值本应有数（如漏导出），勾稽超差会以 E 级拦截。

**规则 → 行的挂接原则**：

- **表级规则不挂行**，在主界面结果区顶部汇总条展示：VC-01~05（文件/结构）、VC-12（试算平衡）、VC-22/23（导出阶段）；
- **报表勾稽挂到对应输出行**：资产负债表不平衡（VC-13/14）→ 资产总额/负债总额/所有者权益行 ✗；利润表三级勾稽（VC-15/16）→ 营业利润/利润总额/净利润行 ✗；现金流量表链条（VC-17）→ 经营活动净额行 ✗——含义是"该行数据来源表内部不自洽，数值不可信"；
- **跨表规则挂相关行为 ⚠**（VC-18 货币资金、VC-19 抽查清单科目）；
- 每个非 ✓ 行必须携带：**规则编号、级别、原因、源定位（表/行/单元格或科目）**，点击可钻取（见 9.2）。

行级状态同步写入计算日志（每项记录 `validation` 字段）与审计摘要（70 行状态矩阵），保证"**预览所见 = 日志所记 = 导出所得**"。

- **布局原则**：计算与核对是核心功能，占据右侧可拉伸主区；输入设置等辅助功能在左侧窄栏（`QSplitter` 分隔条可拖拽，范围 340~430px）；
- **输入方式二选一**：单选「单个工作簿」或「**文件夹 / 压缩包**」，切换时仅显示对应输入区：
  - 文件夹：按文件名关键词（表名）自动识别 4 张报表（递归扫描子目录）；单个含全部 4 张表的文件也会被识别为工作簿；
  - 压缩包：解压到临时目录后同上（防路径穿越，读取完成后自动清理）；
  - 每个报表文件内优先取与表名相同的 Sheet，否则取第一个 Sheet；
  - 未选择或识别不全时，按当前模式给出针对性提示（缺哪张表、期望文件名含表名）；
- **保存位置**：默认本机下载目录，弱化为一行小字，点「更改…」才展开选择；
- **人工数据**：2×2 紧凑排布，自动带出上期填报（`~/.fin_summary_state.json`），本月有变动再改；
- 点击「开始计算」生成 run_id，计算在工作线程执行，UI 不假死；完成后结果表格直接填充；
- 结构校验失败：弹窗列出**财务语言**的定位信息（哪张表、期望表头、实际读到什么、怎么修），停留主界面；
- 本版**移除**：预览明细 CSV、匹配诊断报告、打开日志目录（改为「查看底稿」对话框）。

### 9.2 结果与校验区（主界面内嵌）

按输出表结构**逐行展示 70 个计算项**，项目列按模板 A 列**层级缩进**显示（半角缩进转全角，防止塌缩；与输出文件完全一致），每行带 emoji 状态图标（✅/⚠️/❗/⏳/⚪）与**原始值(万元)/取整后(万元)对比**，与输入区同屏（布局见 9.1 草图下部），供导出前人工逐项审核。

**交互规则**：

- **行状态**（6.1 模型，V2.8 起 emoji）：❗ 行红色高亮、⚠️ 行橙色、待填报行灰色；汇总条与图例置顶（图例加粗常色），不占用行；
- **数据核对（V2.9 重构）**：两行结构，不用「｜」分隔长串——
  - **汇总行**（加粗）：全部通过时 `数据核对：✅ 四张报表全部通过`；有问题时 `数据核对：❗ N 项错误　⚠️ N 项警告`（只列非零项）；
  - **明细行**：全部通过时说明核对范围（资产负债平衡、三表勾稽、借贷平衡、跨表账账相符、行次连续性）；有问题时**逐行一条**列出（每条含表名、中文标题与**万元**差异金额），红色显示；
  - ℹ 级提示（如「其他应收款」已知口径差异）单独作提示行，不计入错误/警告；
  - 核对原理（会计恒等式交叉验证）在第四步 ⓘ 帮助中说明；
- **原始值对比列**：每行同时展示原始值（÷10000 后，千分位 2 位）与取整后（整数千分位），明细面板可见完整链路，便于人工对比复核取整是否可信；
- **舍入临界高亮**：原始值小数部分落在 [0.45, 0.55] 时该单元格高亮（如带息负债 58,719.53 → 58,720）——此场景正是样例数据出现 58719/58720 手工差错的情形；仅作显示提示，**不改变行级状态与导出条件**；
- **取数来源列**：只显示来源简述，格式统一为「表·项目·字段」——报表类如「利润表·营业收入·本年实际数」「资产负债表·应付账款·期末余额」，科目类如「科目余额表·长期借款_银行贷款·期末贷方」（**不带科目代码**，代码保留在日志）；公式行显示可读公式如「营业盈余+生产税净额+资产折旧+劳动者报酬」；不显示工程表达式；
- **钻取**：点击任意行，下方明细面板展示财务语言完整链路——`取数：利润表·营业收入·本年实际数（利润表!E3）` → `98,858,806.30 元 → 9,885.88 万元` → `取整：9,886 万元`；多来源项逐项列示后给合计；据此可人工复算；
- **空源提示**：源单元格为空的行，状态图标带 tooltip「该行对应的报表单元格为空，按 0 填列（结果正确，仅提示）」，行状态仍为 ✓（V2.4 语义）；
- **人工项就地编辑**：双击"待填报"行直接输入数值（单位：人），保存后同步回主界面人工数据输入框，并自动重算依赖它的公式项（劳动者报酬 → 增加值等），状态实时刷新；
- **人工确认（V2.10，导出前置条件）**：
  - 「确认无误」列对**可确认行**（✅ 正常 / ⚠️ 需确认 / ⚪ 固定值）均可勾选；❗ 错误行须先修正、⏳ 待填报行须先补数（仅 CLI 未提供 --manual 时出现；界面端人数 0 为有效值，不会待填报）；
  - 工具条提供「**全部确认 / 全部取消**」与进度显示（已确认 N / M 项），避免逐项点击；
  - **导出条件**：无 ❗ 错误、无 ⏳ 待填报、且**全部可确认项已确认**，三者缺一导出禁用（按钮置灰 + 原因提示）；
  - 就地编辑人工项后，**数值发生变化的行（含依赖它的公式行）自动取消确认**，须重新核对；
  - 重新「开始计算」生成新 run_id，确认状态随之重置（新运行重新审核）；
  - 确认记录（行次、项目、状态）写入操作日志与审计摘要；
- **筛选**：`只看需要关注的行`开关（❗/⚠️/待填报）；
- **重算**：修改输入或人工数据后再次点击「开始计算」会生成**新 run_id**；原运行的计算与校验日志保留，运行状态标记"已计算未导出"。

### 9.4 导出动作

1. 点击「导出 Excel 报表」（**条件满足方可点击**：无 ❗ 错误、无 ⏳ 待填报、全部项已人工确认；未满足时按钮置灰，悬停提示缺什么）：写临时文件（C/D 列全写值）→ 回读复核（VC-23）→ 重命名为正式文件 → 计算输出 SHA256 → 补全审计摘要（含逐项人工确认记录与导出时间）；

3. 导出失败（目录只读、文件被占用等）：清理临时文件、明确提示，不产生半成品。

## 10. 技术方案

### 10.1 技术选型

| 项 | 选择 |
|---|---|
| 语言 | Python 3.11+ |
| 界面 | PySide6 |
| Excel 读写 | openpyxl：读取用 `read_only=True + data_only=True` 流式加载；写入保留格式。**不引入 pandas**（2000 行量级无需，可减包体约 70MB、加快启动） |
| 公式依赖排序 | 标准库 `graphlib.TopologicalSorter`（FORMULA 项 DAG 拓扑排序，配置新增公式项自动排层） |
| 金额计算 | `decimal.Decimal`，禁止 float 参与金额运算 |
| 打包 | PyInstaller `--onedir`，主程序 `FinSummaryTool.exe` |
| 网络 | 无任何网络依赖，全程离线 |

### 10.2 分层架构

| 层 | 职责 |
|---|---|
| UI 层 | 文件选择、月份/人工数据录入、生成、校验展示、日志查看 |
| 应用服务层 | 编排流程、run_id 生成、阻断/确认控制 |
| 解析层 | 读 4 张输入表，定位 Sheet/列/行，名称规范化匹配 |
| 计算引擎层 | 按映射配置取数、Decimal 计算、公式依赖排序 |
| 校验层 | 第 6 章规则执行，输出分级结果 |
| 日志层 | 操作/计算/校验/异常日志、审计摘要 |
| 配置层 | `mapping.json`、`settings.json` 加载与 Schema 校验 |
| 输出层 | 模板副本写入、格式保留、回读复核 |

计算、校验、日志、解析模块不依赖 UI，可独立单元测试。

### 10.4 处理流程

1. 用户上传报表（**单个工作簿 / 文件夹 / .zip 压缩包**三选一，后两者按文件名关键词自动识别 4 张报表），选择报表期间（人工数据自动带出上期填报），点击「开始计算」（生成 run_id）；
2. 解析输入（压缩包解压到临时目录、读取完成后清理），执行 VC-01~05/VC-24 结构校验，失败以财务语言弹窗定位报错并停留主界面；
3. 加载 `mapping.json`，Schema 校验，执行名称匹配（VC-08~11），匹配失败定位到具体输出行；
4. 科目余额表试算平衡（VC-12，**按一级科目汇总**）与报表勾稽（VC-13~19）、行次连续性（VC-25）；
5. 按 `graphlib` 拓扑排序逐项计算（取数项 → 公式项），逐项写计算日志与行级状态（6.1）；
6. **结果与核对同屏展示**（9.1/9.2）：行级 ✅/⚠️/❗/⏳/⚪ 展示，项目列层级缩进，数据核对按表分组；人工项就地补录，逐项勾选「确认无误」（或全部确认）；
7. 用户点击「导出 Excel 报表」（条件：无 ❗、⚠ 全部确认、待填报=0）：写临时文件（C/D 列全写值）→ 回读复核（VC-23）→ 重命名正式文件；
8. 计算输出 SHA256，写审计摘要（含人工审核确认记录、导出时间、结构快照）；
9. 提示文件名、保存位置与汇总；可「查看底稿」追溯本次运行。

未导出（用户返回修改或关闭）的运行：计算与校验日志保留，运行状态标记**"已计算未导出"**，不产生任何输出文件。

### 10.6 取数链路钻取（原匹配诊断报告，V2.6 起由界面承载）

V2.6 起移除独立的匹配诊断报告与预览明细 CSV。取数链路改由主界面**钻取明细**承载：点击结果区任意行，明细面板以财务语言展示完整链路——`取数：{来源表}·{项目}·{字段}（{单元格地址}）` → `{原始金额} 元 → {万元} → 取整 {值} 万元`；多来源项逐项列示后给合计；公式行展示可读公式与各项取值。财务人员无需理解匹配机制，即可对照原报表逐项复算。

### 10.7 输出写入策略（全写值）

源模板"生成的数据"Sheet 中部分行为 Excel 公式。若导出时保留公式，openpyxl 写出的文件不含公式缓存值，**回读复核（VC-23）无法执行**，且预览值与打开文件所见可能不一致。且 V2.14 起输出改为全新生成的工作簿（不复制模板），C（原始值）/D（取整后）两列一律写入计算值，确保：**预览所见 = 日志所记 = 导出所得**。C 列存全精度 Decimal（显示 2 位、千分位），×10000 可精确还原到元。输出不含颜色样式与计算逻辑列。

## 12. 验收标准

1. 上传模板样例数据（1 工作簿 4 Sheet 方式），录入月份，10 秒内完成计算并在主界面展示结果（人工项可在结果表格中补录）；确认后导出，格式与模板一致；
2. 输出 70 行数值与 4.2 映射表规则逐项复算一致（样例中 2 处模板现值差错按工具计算值为准，见 13.3）；
3. 科目余额表借贷不平衡（按一级科目汇总）时对应行标 ✗，导出禁用并显示差额；
4. 映射匹配失败（科目改名/缺失）时对应行标 ✗，并提示"表名 + 行号 + 项目名"；
5. 删除任一必需 Sheet / 列时弹窗阻断并给定位信息；
6. 未录入人工数据时对应行为"待录入"，导出禁用；
7. 每次运行产生计算日志与校验日志，成功运行产生审计摘要；
8. 计算日志可据其人工复算每个输出值；
9. 输出文件回读复核通过后才落正式文件名；
10. 全程断网功能正常；文件损坏、输出目录只读等异常不崩溃、有明确提示；
11. 主界面结果区按输出表逐行展示 70 项及行级状态；存在 ✗ 行时导出按钮禁用；
12. ❗ 错误行未清零、⏳ 待填报行未补齐、或有任何一项未「确认无误」时，导出按钮禁用；确认记录写入审计摘要；

## 13. 开放问题清单（需业务确认）
### Q1 输入形态

4 张表以"1 个工作簿含 4 个 Sheet"、"文件夹"还是".zip 压缩包"提供？本方案默认**三种都支持**（V2.8 起界面提供工作簿 / 文件夹 / 压缩包二选一，后两者按文件名自动识别），请确认实际使用方式以简化界面。

### Q2 舍入口径（重要）
表头注明"除 10000 并四舍五入保留 0 位"，但样例数据存在矛盾：
- 税金及附加：738060.28 ÷ 10000 = 73.806，四舍五入应为 **74**，模板现值 73；
- 带息负债总额：587195310 ÷ 10000 = 58719.531，四舍五入应为 **58720**，模板现值 58719（若**分项先舍入再求和**：16380+360+37000+4979 = 58719，则吻合）。

请确认口径：① 先汇总后舍入（默认建议）；② 分项舍入后再汇总；③ 截断。**本方案默认按模板表头口径：先汇总、后 ROUND_HALF_UP**，工具会以计算值覆盖样例差错并在校验中提示差异。

### Q3 固定资产投资额的"下限"语义
规则为"计算值小于 749 时按 749 填列"，但 749 恰为本期样例现值，疑为"上期数/计划数/承诺数"。请确认该下限的业务含义与数据来源，方案中已将其设计为**每期可配置参数**。

### Q4 应交/已交所得税口径
D 列注明"填 0"，但科目余额表存在 `应交税费_企业所得税` 明细科目（本期无余额）。若未来期间有余额，是否应按科目计算？方案中将其设计为 CONST(0) 且可切换为 TB 取数。

### Q5 输出文件组织
输出为"每期一个独立文件"，还是向同一文件**按月追加 C 列**（形成多期对比表）？本方案默认每期一个文件。

### Q6 人工数据的提供方式
平均职工人数等 4 项按"人力提供，不用管"处理，方案中要求每期必须录入。是否需要支持从人事系统导出的固定格式表格批量导入？

### Q7 科目名称变更风险
取数依赖科目名称全称精确匹配（不依赖编码体系）。年度科目体系调整（改名、增设明细）时需同步更新 `mapping.json`。是否需要提供"映射维护界面"或每年由财务提供新版映射表？

### Q8 历史期间输入
利润表含"上年实际数"、现金流量表含"上年同期金额"列，本期需求只取本年累计。是否需要支持"上年同期"取数以生成对比数据？

### Q9 `.xls` 旧格式
是否需要直接支持 `.xls`（当前方案：提示另存为 `.xlsx`）？
