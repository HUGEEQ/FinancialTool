# FinSummaryTool 客户端打包说明

面向最终用户（财务人员）分发**可执行文件**——**目标电脑无需安装 Python**，
也无需 VC++ 运行库（解释器、PySide6、openpyxl、Qt、微软运行库全部打进程序内）。
方案：**PyInstaller onedir**（单文件夹分发，主程序 `FinSummaryTool.exe`）。

> PyInstaller 不支持跨平台打包：Windows 的 exe 必须在 Windows 上构建，
> macOS 的 app 必须在 macOS 上构建。途径见下。

---

## 一、Windows 客户端（优先）

**不必须有实体 Windows 电脑**，三条途径任选：

| 途径 | 适用场景 | 操作 |
|---|---|---|
| **A. GitHub Actions 云构建（推荐，零成本）** | 没有 Windows 设备 | 项目推到 GitHub → Actions → Build Windows Client → Run workflow → 下载构建好的 zip |
| B. 任意 Windows 电脑/虚拟机一次性构建 | 手边有 Win 电脑，或 Mac 上的虚拟机（Parallels/VMware/VirtualBox） | 拷项目过去，双击 `scripts\build_windows.bat` |
| C. 团队 CI（GitLab 等有 Windows runner） | 已有 CI 体系 | 复用 bat 或 workflow 中的命令 |

**方式 A：GitHub Actions**——仓库已内置工作流 `.github/workflows/build-windows.yml`，支持手动触发；
构建产物在 Artifacts 下载，无需任何本地 Windows 环境。流水线含四道关卡：安装依赖 → 打包 → **自检**（资源解析/日志可写）→ **Bundle 校验**（exe + VC 运行库 + Qt 齐全）→ 压缩上传。

**方式 B：Windows 本机构建**——要求 Windows 10/11 64 位 + Python 3.11+（python.org 下载，勾选 Add to PATH）：

```
1. 把整个项目文件夹拷到 Windows 电脑
2. 双击 scripts\build_windows.bat
```

脚本自动完成：建独立构建环境 → 装依赖 → 打包 → 自检 → Bundle 校验 → 压缩。

产物：
- `dist\FinSummaryTool\` —— 客户端程序目录（**整个文件夹**发给用户，双击 `FinSummaryTool.exe` 即用）
- `dist\FinSummaryTool-windows-x64.zip` —— 可直接分发的压缩包

---

## 二、macOS 客户端

在 Mac 上运行：

```bash
bash scripts/build_macos.sh
```

产物：`dist/FinSummaryTool.app`（约 73MB）。

**分发注意（未签名）**：macOS 对未签名应用默认拦截。用户首次打开需**右键 → 打开 → 再点"打开"**
（或在 系统设置 → 隐私与安全性 中点"仍要打开"）。如需消除该提示，需 Apple 开发者账号做签名公证。

---

## 三、目标电脑环境要求（重要）

| 要求 | 说明 |
|---|---|
| **无需安装 Python** | 解释器与全部依赖（PySide6/openpyxl/Qt）已打包进 `_internal`，这是 PyInstaller onedir 的设计目的 |
| **无需 VC++ 运行库** | PyInstaller 会把 `vcruntime140.dll` 等微软运行库一并打入；CI 的 Bundle 校验与本地 bat 均会检查其存在，缺失在构建期即报错，不会到用户机器上才发现 |
| 系统 | Windows 10/11 **64 位**（x64 产物不兼容 32 位系统与 Win7；如用户用 Win7/32 位，需用对应位数的 Python 重新构建） |
| 磁盘 | 约 200MB 空闲（程序 73MB + 日志/输出增长） |
| 网络 | 不需要——工具全程离线 |

### 客户端体积（约 73MB，正常量级）

| 构成 | 大小 | 说明 |
|---|---|---|
| Qt 界面库（QtCore/QtGui/QtWidgets + 插件） | ~20MB | PySide6 必需；已剔除 QtPdf/QtQml/QtQuick/QtNetwork 等用不到的框架（98MB→73MB） |
| Python 运行时 + openpyxl 等 | ~10MB | 必需 |
| 程序与资源（mapping.json、summary_template.xlsx） | <1MB | 计算规则与项目名称基准 |

文档、测试、样例数据均不打包。Windows 版通常比 macOS 版略小（60~70MB）。

## 四、分发给用户的注意事项

| 事项 | 说明 |
|---|---|
| 杀毒软件/SmartScreen 误报 | PyInstaller 打的未签名 exe 可能被 Windows SmartScreen 提示"未知发布者"：用户点"仍要运行"即可。彻底消除需代码签名证书 |
| **完整分发** | 必须把 `FinSummaryTool` **整个文件夹**一起分发（exe 依赖同目录 `_internal`），不能只拷 exe 单文件 |
| 升级 | 覆盖整个文件夹即可；用户数据不受影响（见下） |
| 首次启动 | 稍慢（解压加载），属正常 |

---

## 五、客户端数据存放位置（与程序目录解耦）

| 数据 | 位置 |
|---|---|
| 输出报表 | 默认**下载目录**（`~/Downloads`），界面可改 |
| 计算底稿/日志 | `~/FinSummaryTool/logs`（打包模式自动写入用户主目录，双击启动不受程序目录权限影响） |
| 上期人数记忆 | `~/.fin_summary_state.json` |
| 计算规则、项目名称基准 | 已打包进程序内（`mapping.json`、`summary_template.xlsx`） |

卸载 = 删除程序文件夹 +（可选）删除上述用户目录。

---

## 六、打包自检

构建流程会自动执行；也可手动验证客户端内资源是否完整：

```
FinSummaryTool.exe --selftest                          (Windows)
FinSummaryTool.app/Contents/MacOS/FinSummaryTool --selftest   (macOS)
```

输出 `SELFTEST OK` 即通过（校验 70 项计算规则、70 个项目名称、日志目录可写）。
Bundle 校验（CI 自动）额外确认 `vcruntime140*.dll` 与 `Qt6Core.dll` 在包内。

---

## 七、配置更新（计算逻辑变更时）

计算规则外置于 `fin_summary/resources/mapping.json`（已打包在内）。
改规则后的发布流程：改 `mapping.json`（并升 `config_version`）→ 重新构建分发。
输入报表格式变化无需改程序——列定位是表头驱动的。
